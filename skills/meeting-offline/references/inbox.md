# 录音收件箱：手机录完，电脑自动转写

用户把手机录音存进一个固定文件夹（默认 `iCloud 云盘/会议录音`），电脑在后台：等文件同步完整 → 按内容去重 → 排队 → 用本地引擎转写并准备好说话人卡片 → 弹通知提醒回来确认。`scripts/inbox.py` 只用本地识别，不上传录音；谁是谁、术语和纪要仍然回到 AI 工具里由用户确认。

## 开启（一次，需要用户同意）

开启会在电脑上装一个后台任务，属于系统改动。用户说“手机录完能不能自动处理”“每次都要等转写”时，先说明三件事再问是否开启：

1. 只用本地 FunASR 或 Whisper 转写，录音不会上传；需要本地引擎已经装好（[转写方案](transcription-options.md)）。
2. macOS 上是一个登录后在后台运行的 launchd 任务，文件夹有变化或每 2 分钟检查一次，一次只转一个，低优先级运行。
3. 随时可以用 `inbox.py remove` 关掉。

用户同意后：

```bash
python3 <skill-dir>/scripts/inbox.py setup --dry-run                  # 先看会装什么（文件夹、引擎、后台任务内容）
python3 <skill-dir>/scripts/inbox.py setup --engine funasr            # 开启；--folder 改文件夹，--engine whisper --model small 用 Whisper
python3 <skill-dir>/scripts/inbox.py status
```

手机端怎么把录音存进这个文件夹，见 [用手机录会议](iphone-recording.md)（方法二的快捷指令最省事）。

- **macOS 权限**：iCloud 云盘、下载、桌面受系统保护。第一次运行时如果收到“没有权限读取”的通知，请用户打开 系统设置 → 隐私与安全性 → 文件与文件夹（或“完全磁盘访问权限”），允许 `setup` 输出里 `python` 那一项的程序访问，不用重装。
- **Windows / Linux**：`setup` 只保存选择（`mode: manual`），不装后台任务。用户愿意时在终端运行 `inbox.py watch`，或用系统的计划任务每几分钟运行一次 `inbox.py run`。
- 换了 Python 环境或挪动了技能目录，重新运行一次 `setup`（正在转写的那条会中断，之后自动重试）。
- 后台每次运行只在 `inbox.log`（数据目录里）记一行，超过 1 MB 自动换新文件。

## 它怎么判断一条录音能处理了

| 状态 | 含义 |
| --- | --- |
| `syncing` | 刚看到，或还在写入 / 同步；iCloud 里没下载的文件会请求下载（`note: 等待 iCloud 下载`） |
| `queued` | 大小和修改时间至少 20 秒没变（隔开的两次检查都一样），排队等转写 |
| `transcribing` | 正在转写；电脑休眠或进程被结束时，下次运行自动改成失败并重试 |
| `ready` | 转写好了，工作区和说话人卡片已经准备好，等用户确认 |
| `done` | 这场的纪要已经发布 |
| `duplicate` | 内容（SHA-256）和排队中、已转写的录音或已有工作区相同，不再转写；失败或移走的那条不算，换个名字放回来会重新处理 |
| `failed` | 出错了，自动重试，3 次都失败时通知用户，`error` 里是原因 |
| `gone` | 还没处理就被移走或删除；放回来会重新处理 |

用 Whisper 时转写本身的断点照常生效：重试时已经算好的文字和说话人分离结果直接复用，不会从头再来；FunASR 一步完成识别和分离，重试时整段重新识别。同一个文件名下出现了新的录音（语音备忘录常用“新录音 3”这样的名字），按新录音处理，旧记录保留。

## 给助手的说明

- 用户说“整理最新的会议录音”“手机上那个会转好了吗”时，先运行 `inbox.py status`，看 `ready` 列表：
  - 有一条：直接用它的 `workspace` 从[角色认领](roles.md)开始，不要重新转写；告诉用户这是哪个文件、几位发言人、说话人分离的情况（`speaker_separation`、`coverage`，规则同[角色认领](roles.md)）。
  - 有多条：按时间列出文件名和发言人数，让用户选。
  - 没有：看是否有 `syncing`、`transcribing`、`failed`，如实说明在等什么或出了什么错；收件箱没开（`settings` 为空）就按平常流程找录音。
- 收件箱里的录音同样要归档（[归档](archive.md)）。归档会把原文件移出收件文件夹，这是正常的，不影响记录。
- 通知只写文件名和发言人数，不写会议内容。后台任务不会写纪要、不会认人、不会写入长期记忆，这些仍按主流程由用户确认。
- 用户想让后台改用 Qwen 云端转写时，说明收件箱只做本地识别：上传要按每一条录音单独征得同意，所以这类录音请在 AI 工具里正常处理。
- 用户说不要了：`inbox.py remove`，并告诉用户已经关掉；已转写好的工作区和收件文件夹里的录音都保留。
