# 本地角色库与术语库

记忆库由 `device_context.py init` 返回的 `memory` 路径定位，默认在 `~/.meeting-offline/devices/<device-id>/memory.json`（旧版本的 `~/.meeting-minutes/` 或 `~/.codex/meeting-minutes-memory/` 存在时继续使用），同一台电脑上的各 AI 工具共用，与技能文件分开，只在本机使用，不随技能包导出，也不自动发送给转写服务。可用 `scripts/memory.py --store <path>` 指定团队或项目独立的库；不要自动跨库混用角色。

## 每次会议开始时

读取本地库，按当前组织、团队、议题和时期检索相关的角色和术语，不把整库塞进上下文。库不存在时运行 `python3 <skill-dir>/scripts/memory.py init`；可用 `show` 查看，再用文件搜索定位。

- **角色档案**：只记用户确认的姓名/角色、别名、所属范围、职责/关注议题、可区分的观点线索及确认来源。用户只给职务时建“角色”档案，不虚构自然人。角色和人不是同一种实体；同名角色可属于不同组织或多人。
- **术语库**：记标准写法、已确认的误识别/口头别称、所属业务、简要含义和确认来源。产品名、人名、组织名、内部系统名都可积累。有歧义时保留多个候选及适用范围。
- 给说话人提“候选角色 + 匹配依据”，允许没有候选。职位相似或主题相同只说明职责接近，不能证明是同一人。
- 卡片可预填候选但写明待确认：复核页面里候选已经选好，用户核对后保存；在对话里认领时用户可一次回复“候选都对，4-B 改成……”。历史映射不自动证明本次说话人身份。
- 术语用于辅助解释和校对时保留原转写，首次重要替换标注标准名及原识别形式。只用与上下文吻合的词条，不把近音词全局机械替换；价格、数字与具体承诺不从词库推断。

## 术语复核

默认提供选择卡片，让用户看原文判断，不要求从空白回忆。每组给出原识别变体、带时间与说话人的逐字原文、回听入口、少量标准词候选及依据。候选可来自相关已确认词库、转写变体或明确标注的推测；转写不是正确拼写的证明。始终支持自定义、“不同含义，不合并”和“暂不确定”。候选 JSON 格式见 [本地复核](local-review.md#术语选择与词库)。

- 用户选定标准词并勾选原文后才入库；标准写法可以就是原写法（只积累，不替换）。
- 保存适用业务范围和确认来源，标准词与误识别对应关系分别记录。
- 部分段落的纠正只作用于所选片段，不记作通用别名；“不同含义”“暂不确定”只留任务复核记录，不升格为已确认词。
- 助手可以准备候选和证据，不能替用户选择未确认的标准词。
- 替换只命中独立出现的写法：已是标准写法的部分、更长的已知写法（如纠正“王总”时的“王总监”）、英文单词内部都不会被改。库里没有记录的更长词无法自动识别，需要时把它作为候选写法列入卡片。

## 积累与修订

用户确认角色或纠正术语后，在同一轮存入库，无需再为本地保存单独询问。纠错和角色变动保留修订记录与确认依据；新的临时判断不覆盖旧的确认。

```bash
python3 <skill-dir>/scripts/memory.py upsert \
  --kind role --entry /path/to/confirmed-role.json --user-confirmed
python3 <skill-dir>/scripts/memory.py upsert \
  --kind term --entry /path/to/confirmed-term.json --user-confirmed
```

`--user-confirmed` 只能在当前对话确有用户确认依据时使用，不是让模型自行确认的开关。JSON 格式见 `python3 <skill-dir>/scripts/memory.py --help`。原始转写是待校对材料，不足以作为入库依据；未确认的候选留在任务状态里，避免下次把自己之前的猜测当证据。

只积累对辨认和纪要有用的少量线索，不在角色/词条中保存整场转写、无关私人细节或密钥；会议工作区的来源快照与档案条目分开保存。用户要求改名、纠错或停用某条记录时同步更新；停用设为 inactive，检索时排除。

## 对识别准确度的作用

默认只改善角色候选、转写后术语校对和结论归属。只有转写工具确实支持并实际传入了热词参数，才能说词库参与了 ASR 识别；否则说明只是转写后校对。把档案或术语发给外部服务仍需在用户授权的具体任务范围内，不顺带上传整个记忆库。
