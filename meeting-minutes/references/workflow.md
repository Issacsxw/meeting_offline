# 固定流程与默认模板

主产品是简洁、有结论、有 Todo 的会议纪要；角色与术语库随每场会议持续完善。

先运行 `scripts/device_context.py init`，按返回的本机数据路径执行。不同设备的记忆与缓存从空目录开始，详见 [设备隔离](portability.md)。

## 一次会议

1. **指定来源并归档录音**：用户给出本地录音，或从最近录音中选择。选定后按 [归档方法](archive.md) 将原文件移动到 初始化返回的 `archive` 目录下的 `日期_主题/`，同步工作区路径；仅列举最近录音时不移动。复用已有转写与工作区，避免重复上传或计费。Apple 语音备忘录托管库保持只读，先导出为普通本地文件再归档。
2. **取得转写**：有需要时按用户对当次录音的授权使用 Qwen；阿里云默认直连。保留时间戳和说话人，使用与业务相关的已确认热词，不上传整个本地库。具体模型能力与上传边界以转写流程为准。
3. **集中复核**：按每位说话人的实质观点、原话与时间定位给出角色候选；同时给出影响理解的术语原文与少量候选。用户确认身份、选择术语或填自定义写法；已明确的内容不重复询问，不把历史身份匹配当成本场确认。
4. **整理会议正文**：综合整场对话，写主题、时间、姓名、概要、按议题归纳的要点和主要 Todo。区分决定、方向与建议；负责人和期限只写有依据的内容。完整逐人观点与证据留在底稿。
5. **双格式交付与归档**：按暖白模板生成可编辑 HTML，并由脚本直接无头导出对应 PNG；打开 PNG 检查排版。用户之后改 HTML，可在页面里点导出图片，或由助手对修改版运行 `render_png.py` 出新图。将两份文件放入该会议的录音所在文件夹，交付文件夹链接。主题在上，时间与姓名在下；未知时间隐藏，不显示处理提醒。无需再问“是否开始生成纪要”。
6. **本地积累**：把用户已确认的角色、别名和术语写入本地库；保留复核与修订依据。用户在 HTML 中普通改稿不自动改写角色/术语库，明确身份或术语纠正再同步积累。

用户日常只需指定会议，并确认确实有疑问的角色或术语。普通技术重试、排版与导出由助手完成；新录音的云端传输仍须处于当次授权范围。

## 已确认视觉

- 全文暖白 `#FAF9F5`，陶土色 `#D97757`，正文深灰 `#30302C`，浅灰分隔线 `#E8E6DC`。不使用深色页首或深色 Todo 区。
- 标题和概要采用宋体/衬线气质，正文保持清晰的黑体/无衬线；数字采用 Lora 风格。HTML 与 Canvas 使用相同字体栈，本机未装目标字体时回退到系统宋体、黑体与 Georgia，不联网加载字体。
- 时间与参会人位于主题下面，参会人不附岗位。概要回答整场会议的核心问题与推进方向；要点按议题组织，不按人名排列。
- Figma 是视觉母版，本地 `assets/minutes.html` 是日常交付模板。修改视觉后同步 HTML 和 Canvas 导图，再更新已交付图片，避免只改 Figma。

HTML 保存与图片导出的具体方法见 [双格式交付](publish-html.md)。
